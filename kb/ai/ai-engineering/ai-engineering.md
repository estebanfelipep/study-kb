# ai-engineering — index

This folder covers building AI-powered systems with Claude: the API, prompts and context, tools, agents, scoping and designing a feature, and evaluating it.

## How to read this folder

- **Before:** [core-concepts.md](../core-concepts.md), for what generative AI is, what the AI engineer role involves, and how foundation models and RAG work.
- **Order:** the Claude API and prompting first, then tools and agents, then taking a feature from PoC through discovery to a design document, and evals last for measuring it.
- **After:** [aws-ai-engineering](../../aws/aws-ai-engineering/aws-ai-engineering.md), for how AWS services orchestrate model chains.

## Files (in reading order)

- [claude-api-foundations.md](claude-api-foundations.md): from Anthropic's Claude course: the four model tiers (start with Sonnet, move up or down only on an eval), model choice vs reasoning mode vs prompting mode, tokens, the context window and sampling, the sync, streaming, async and Message Batches call patterns, how to handle a stream that stops early and streaming with tool use, multimodal input (base64 vs URL vs Files API, the image token formula) and the settings that change the response: extended thinking (the thinking block, its cost and the carry-back rule) and structured outputs (JSON outputs vs strict tool use, their trade-offs and when they still fail to parse). Read when: you need which Claude model or reasoning mode to pick, how to call the API for a given workload, how to send an image and what it costs, whether to turn thinking on, what structured outputs cost, or why a tool-using request with thinking was rejected.
- [prompt-and-context-engineering.md](prompt-and-context-engineering.md): how prompt engineering (writing the prompt) differs from context engineering (assembling the context on each turn). Prompt structure and anatomy, system prompts, role prompting, zero-, one- and few-shot, chain-of-thought and prompt tips; diagnosing a failed prompt by failure type; the limits of long contexts, compaction strategies and triggers, the four strategies for staying in budget (pruning, compaction, clearing, subagent handoffs), prompt caching (what makes a hit, the 5-minute and 1-hour lifetimes), token counting, and evaluating a memory-enabled agent. Read when: you need how to write a prompt that gets better output without changing the model, which strategy fits a session near the context ceiling, or how to cut the cost of a repeated prefix.
- [tool-use.md](tool-use.md): how Claude picks a tool by its description, the fix when descriptions overlap (an exclusion sentence, or merging into one tool with a type parameter), returning a failed tool's error with `is_error`, and MCP: a server supplies ready-made tools, resources and prompts over stdio (local) or Streamable HTTP (remote), how to set one up in Claude Code (transport, scope, config location), how it authenticates (OAuth, API key in an environment variable, stdio), and the context cost of each connected server. Read when: Claude calls the wrong tool, a tool fails and Claude must react, you're writing tool descriptions, you're deciding between hand-written tools and an MCP server, or you're choosing where an MCP server's config and secrets live.
- [agent-orchestration.md](agent-orchestration.md): agentic systems: workflows vs agents and the decision rule between them, the agent loop, the five workflow patterns (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) and what orchestrator-workers costs in tokens, the three wiring paths (Messages API, Agent SDK, Managed Agents), where to put human-in-the-loop checkpoints, the four agent memory scopes, and Skills for carrying instructions across tasks, including how each runtime loads them. Read when: you need whether a task calls for a workflow or an agent, which workflow pattern fits, who should run the agent loop, where an agent needs a human checkpoint, how an agent should remember across sessions, or how to carry repeatable instructions between tasks.
- [genai-poc.md](genai-poc.md): building a generative AI proof of concept: scoping, model selection and evaluation, performance testing, and value calculation, then packaging the build as a reusable accelerator (what stays in the core, what becomes a parameter, the review bar for shared infrastructure). Read when: you need how to scope, evaluate or justify a generative AI PoC, or how to package a finished build so another engagement can reuse it.
- [stakeholder-discovery.md](stakeholder-discovery.md): from Anthropic's Claude Certified Architect course: running a discovery call as structured elicitation (listen, translate, write down), turning stated preferences into constraints, the four requirement questions, functional vs infrastructure requirements (latency, scale, residency, identity), and the translation table. Read when: you need how to turn a stakeholder's business-language request into requirements, assumptions and design constraints, or what makes a requirement checkable.
- [design-document.md](design-document.md): from Anthropic's Claude course: the design document (success criteria, failure handling, cost and latency budget, trust boundary), with retriable vs terminal errors, tool errors, the per-call metrics and budget levers, prompt injection, least privilege, ZDR and data residency, the layers of security, trust boundaries between components, the lifecycle of a Claude application, and choosing a deployment platform (first-party API, Claude on AWS, Bedrock, Vertex AI, Foundry) and pinning the model version. Read when: you need what to write down before building an LLM feature, whether an error is worth retrying, how to budget cost and latency, how to defend an agent that reads content someone else wrote or secure the seams of a multi-component app, which platform to deploy Claude on for a customer, or why to pin a model version.
- [evals/](evals/evals.md): evaluating generative and agentic systems: what an eval is, traces and sessions and how tests complement them, the hill-climb lifecycle from organizational KPIs, the evaluation plan with synthetic test data, and rubrics with the LLM judge (autorater). Read when: you need how to measure, grade or monitor an AI system, or how to turn a business KPI into metrics.
