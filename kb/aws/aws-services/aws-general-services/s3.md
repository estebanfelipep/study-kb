# Amazon S3

Amazon S3 (Simple Storage Service): object storage, its core concepts and storage classes, and its role as the storage layer of a data lake on AWS.

## What it is

Amazon S3 is storage that treats data as **objects within containers (buckets)**. Each object is a file plus its metadata. Unlike block or file storage, S3 is **standalone**: it isn't tied to compute. You interact with it through API calls (PUT, GET) over HTTPS, rather than mounting a file system.

**Analogy:** a valet parking service. You hand over your entire car (the object), get a ticket (the key), and retrieve the whole car later. You can't swap out the steering wheel while it's parked.

In data engineering, S3 is the foundation of a modern data architecture on AWS. The data lake is built on S3 first, because you need a place to put data before you can ingest it. Every source lands here, processed data is usually written back here, and query engines read from it. For what a data lake is, see [data-lakes-and-warehouses.md](../../../data-engineering/data-lakes-and-warehouses.md).

## Characteristics

- **No editing in place:** to change an object, you download it, change it locally, and upload the whole object again. That trade-off enables:
  - **Massive scalability:** store unlimited objects. You can grow from gigabytes to petabytes seamlessly and without disruption.
  - **High durability:** 11 nines (99.999999999%), with data replicated across at least 3 AZs.
  - **Global access:** retrieve objects from anywhere over HTTPS.
- **Pay for what you use:** per GB stored and per request, with no capacity to provision up front.
- **Stores any data type:** structured, semi-structured and unstructured, as raw files, with no extensive preprocessing.
- **Read by key**, any object, any time. There's no order between objects. _(added)_
- **Retention is indefinite**, until an object is deleted or moved by a lifecycle rule. _(added)_
- **Storage only:** S3 doesn't query data itself. An engine such as [Athena](../aws-analytics/athena.md), [EMR](../aws-analytics/emr.md), [Glue](../aws-analytics/glue.md) or Redshift Spectrum reads it, using table definitions from the Glue Data Catalog.
- **Columnar formats:** storing data as Parquet or ORC, with partitioning, makes S3 data cheaper and faster to query with Athena, Redshift Spectrum or EMR. _(added)_
- **Amazon S3 Tables:** S3 buckets built for tabular data in Apache Iceberg format, with automatic maintenance. _(added)_
- **Disaster recovery:** cross-Region replication. _(added)_

### Core concepts

- **Bucket:** a container for objects. Its name must be **globally unique** across all accounts and Regions, because it becomes part of a DNS name (`my-bucket.s3.us-east-1.amazonaws.com`). The *name* is global; the *data* is regional. The exception is **directory buckets** (S3 Express One Zone), which are zonal. Their names include the AZ ID (`my-bucket--use1-az4--x-s3`) and only need to be unique within the Region.
- **Object:** a file plus metadata, up to **5 TB** per object. You upload whole objects, and you can't append to an existing one.
- **Key:** the unique identifier within a bucket, for example `photos/2026/vacation.jpg`. The part before the last `/` is the **prefix**. There are no real folders.
- **Region:** where the bucket physically resides. S3 is a **regional** service, and data is copied across at least 3 AZs automatically.
- **Versioning:** keeps every version of an object, which protects against overwrites and deletes.
- **Not in your VPC:** S3 has no subnet, ENI or security group. You reach it over the internet (IGW or NAT) or through a free **gateway endpoint**, and control access with IAM and bucket policies.

### Use cases

| Use case | Why S3? |
| --- | --- |
| **Backup and storage** | High redundancy, durability (99.999999999%) |
| **Media hosting** | Unlimited objects, 5 TB per object, web-accessible |
| **Software delivery** | Host downloadable apps and installers |
| **Data lakes** | Store petabytes, pay only for what you use |
| **Static websites** | Host HTML, CSS and JS files directly from S3 |
| **Static content** | Serve images, videos and assets for apps |

### Storage classes

**Choose based on access frequency and durability needs.**

| Storage class | Access pattern | Retrieval time | Use case |
| --- | --- | --- | --- |
| **S3 Standard** | Frequent access | Milliseconds | Active data, websites, apps |
| **S3 Intelligent-Tiering** | Unknown or changing | Milliseconds | Automatically moves data between tiers |
| **S3 Standard-IA** | Infrequent access | Milliseconds | Long-term backups, disaster recovery |
| **S3 One Zone-IA** | Infrequent, non-critical | Milliseconds | Secondary backups, re-creatable data |
| **S3 Glacier Instant Retrieval** | Rarely accessed | Milliseconds | Archive with instant access |
| **S3 Glacier Flexible Retrieval** | 1–2 times a year | 1–5 minutes | Long-term archives |
| **S3 Glacier Deep Archive** | Rarely or never | 12 hours | Regulatory compliance (7–10 years) |

- Retrieval times depend on the retrieval tier: Glacier Flexible Retrieval is 1–5 minutes expedited, 3–5 hours standard and 5–12 hours bulk. Deep Archive is within 12 hours standard and within 48 hours bulk. _(added; verify)_

**Rule of thumb:**

- Active data → **Standard**
- Don't know? → **Intelligent-Tiering** (auto-optimizes)
- Backups → **Standard-IA** or **One Zone-IA**
- Archives → **Glacier** variants

### Security

- **Controls:** Block Public Access, bucket policies, encryption (SSE-S3 by default, SSE-KMS, SSE-C), Object Lock and MFA Delete.
- **Bucket policy:** a **resource-based policy** on the bucket, so it **must name a `Principal`**. That can be:
  - an account
  - a role
  - a service such as `cloudfront.amazonaws.com` (OAC, with an `AWS:SourceArn` condition)
  - `"*"`, but only with a condition such as `aws:PrincipalOrgID`, or in a `Deny` such as "deny if `aws:SecureTransport` is false"
- **Cross-account access** needs both the bucket policy **and** the caller's IAM policy, plus the [KMS](../aws-security/kms.md) key policy if the bucket uses SSE-KMS.
- **ARNs:** `s3:ListBucket` uses the bucket ARN, while `s3:GetObject` uses `bucket/*`.
- In data pipelines: default bucket encryption with a customer managed key, and a bucket policy that denies non-HTTPS requests. [Macie](../aws-security/macie.md) scans buckets for PII. _(added)_

### Performance

- **3,500 writes and 5,500 reads per second per prefix.** S3 scales automatically with unlimited prefixes, but a sudden spike can return **503 Slow Down**. Retry with backoff.
- Multipart upload, Transfer Acceleration and byte-range fetches speed up large transfers.

### Event notifications

- Events such as `ObjectCreated` (an overwrite counts) and `ObjectRemoved`, with prefix and suffix filters, can go to [Lambda](../aws-compute/lambda.md), [SQS](../aws-application-coordination/sqs.md), [SNS](../aws-application-coordination/sns.md) or [EventBridge](../aws-application-coordination/eventbridge.md).
- This makes S3 the usual starting point of a serverless pipeline.

### Static websites

Serverless applications often use S3 for file storage and for **hosting static websites**: HTML, CSS, JavaScript and images served directly from a bucket. Put **CloudFront with OAC** (origin access control) in front of the bucket.

S3 **can't** host:

- Server-side rendered applications (SSR)
- Traditional backend applications (PHP, Rails, Django)
- Applications that run server-side code per request

Modern **SPAs** can still run on S3:

- Host the static front-end files on S3.
- Use separate backend services ([Lambda](../aws-compute/lambda.md), [API Gateway](../aws-apis/api-gateway.md)) for dynamic functionality.
- Fetch data with API calls from the client.

Trade-offs:

- ✅ Can build complex apps (e-commerce, social media, and so on).
- ❌ SEO challenges (without SSR or SSG).
- ❌ Initial load performance (large JS bundles).

## Example

- **Addressing an object:**

  ```
  Bucket: my-app-uploads
  Key:    users/123/profile.jpg
  URL:    https://my-app-uploads.s3.us-east-1.amazonaws.com/
          users/123/profile.jpg
  ```

- **API calls** (boto3):

  ```python
  # Upload an object
  s3.put_object(
      Bucket='my-bucket',
      Key='documents/report.pdf',
      Body=file_data,
      StorageClass='STANDARD_IA'  # Choose storage class
  )

  # Retrieve an object
  response = s3.get_object(
      Bucket='my-bucket',
      Key='documents/report.pdf'
  )
  ```

- **Lifecycle:** application logs land in S3 Standard. A Lifecycle rule moves them to Glacier Flexible Retrieval after 90 days and deletes them after 7 years.
- **Data lake flow** _(added)_: raw data from every source lands in S3. Glue or EMR transforms it, and the curated output stays in S3. The hot, heavily queried subset goes into [Redshift](../aws-analytics/redshift.md), or is queried in place with Athena or Spectrum.
- **Serverless portal** _(added)_: an internal data-quality portal has no server to manage anywhere.
  - The React front end is a static website in S3 behind CloudFront.
  - Its buttons call [API Gateway](../aws-apis/api-gateway.md) → Lambda, which reads results from [DynamoDB](../aws-databases/dynamodb.md).
  - Users upload CSV files to a bucket, and each upload triggers a Lambda function.
